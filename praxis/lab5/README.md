# Лабораторная работа №5. REST API

В этой работе нужно реализовать REST API для управления списком задач на Flask: создание, чтение, обновление и удаление задач, а также фильтрацию, поиск, сортировку и пагинацию.

Полная постановка находится в файле [index.md](index.md).

## Что скачать

Для выполнения работы нужны файлы:

- [student.py](student.py) — шаблон Flask-приложения;
- [check.py](check.py) — проверяющая программа;
- [requirements.txt](requirements.txt) — список необходимых пакетов;
- [index.md](index.md) — задание и технические требования.

Сохраните файлы **в одной папке**. Файл `check.py` предназначен для проверки и изменять его не нужно.

## Подготовка рабочего файла

Создайте копию `student.py` с именем `server.py`. Решение нужно писать в `server.py`, сохраняя имена функций, маршрутов и структуру приложения.

Итоговая структура папки:

```text
lab5/
├── student.py
├── server.py
├── check.py
├── requirements.txt
└── index.md
```

## Установка зависимостей

Откройте терминал в папке с файлами и создайте виртуальное окружение:

```bash
python3 -m venv .venv
```

Если в вашей системе команда называется `python`, используйте:

```bash
python -m venv .venv
```

Активируйте окружение в Linux или macOS:

```bash
source .venv/bin/activate
```

В Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

В Windows cmd:

```cmd
.venv\Scripts\activate.bat
```

Установите зависимости:

```bash
pip install -r requirements.txt
```

## Как выполнить работу

1. Откройте `server.py` в редакторе.
2. Реализуйте вспомогательные функции и маршруты по постановке из `index.md`.
3. Не забудьте заполнить начальные данные через `seed()`.
4. Сохраните файл и запустите сервер.
5. Во втором терминале запустите проверку.
6. Исправьте ошибки, перезапустите сервер и повторите проверку.

## Как запустить сервер

В терминале с активированным виртуальным окружением выполните:

```bash
python3 server.py
```

Или, если используется команда `python`:

```bash
python server.py
```

Оставьте сервер работать в этом терминале. Приложение должно быть доступно по адресу `http://localhost:5000`.

После каждого изменения `server.py` остановите сервер сочетанием `Ctrl+C` и запустите его снова.

## Как запустить проверку

Откройте **второй терминал**, перейдите в ту же папку и активируйте виртуальное окружение. Не останавливая сервер, выполните:

```bash
python3 check.py
```

Или:

```bash
python check.py
```

Проверка обращается к уже запущенному серверу. Отдельно запускать `check.py` как сервер не нужно.

После завершения проверка удаляет задачи, созданные во время тестирования, и восстанавливает исходное состояние хранилища.

## Как читать результат

При полном успехе программа последовательно выведет результаты всех этапов и завершит работу сообщением:

```text
10. удаление ... ок

Все тесты пройдены.
Состояние сервера восстановлено (удалено задач: ...).
```

Если проверка не пройдена, программа остановится на первом ошибочном утверждении и покажет `AssertionError` с номером строки в `check.py`. По номеру этапа и тексту условия можно определить, какое требование нарушено.

Сообщение `requests.exceptions.ConnectionError` обычно означает, что сервер не запущен, завершил работу с ошибкой или использует другой адрес либо порт.

## Что проверяется

Проверка состоит из десяти основных этапов и подготовительного шага:

1. **Корневой маршрут и начальные данные:** доступность сервера и значение `seed`.
2. **Подготовка (этап 1.5):** создание 25 дополнительных задач для проверки списков.
3. **Список по умолчанию (этап 2):** структура ответа, размер страницы и количество страниц.
4. **Пагинация (этап 3):** разные страницы, отсутствие пересечений, пустая страница и неверные параметры.
5. **Сортировка (этап 4):** поля `title`, `id`, `created_at`, направления `asc` и `desc`, неверные параметры.
6. **Фильтры и поиск (этап 5):** параметры `done` и `q`, регистронезависимый поиск, сочетание фильтра и сортировки.
7. **Создание (этап 6):** код `201`, монотонность `id` и значение `done` по умолчанию.
8. **Контроль создания (этап 7):** дубликаты, отсутствующий, пустой и слишком длинный `title`, неверный JSON.
9. **Чтение одной задачи (этап 8):** существующая и несуществующая задача, нечисловой идентификатор.
10. **Обновление (этап 9):** PUT, PATCH, коды `200`, `404`, `409` и `422`.
11. **Удаление и идентификаторы (этап 10):** код `204`, пустое тело ответа, повторное удаление и запрет повторного использования `id`.

Локальная проверка помогает самостоятельно подготовить решение. Порядок сдачи и итогового оценивания определяет преподаватель.
