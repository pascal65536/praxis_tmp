# Лабораторная работа 1. Проверка сообщения на спам

В чате появляются обычные, подозрительные и спам-сообщения. Необходимо автоматически классифицировать каждое сообщение и указывать причину присвоения статуса.

Обычные сообщения получают статус `OK`. Подозрительные сообщения требуют внимания администратора. Сообщения со статусом `spam` предназначены для удаления. Обработка изображений, стикеров, видео и других вложений в эту работу не входит.

## Задание

Реализуйте в файле `student.py` функцию:

```python
def solve(data):
    ...
```

Функция принимает один аргумент `data` — строку, в которой ID автора и текст сообщения соединены символом `|`:

```text
author_id|message
```

Например:

```text
41131670|ping
```

Внутри функции необходимо разделить входную строку только по первому символу `|` и преобразовать ID к целому числу:

```python
author_id, message = data.split("|", 1)
author_id = int(author_id)
```

Разбиение только по первому разделителю позволяет сохранить возможные символы `|` внутри текста сообщения. Во всех тестах входная строка соответствует указанному формату. Считывать данные с клавиатуры и выводить их на экран не требуется.

Функция должна возвращать **список из двух строк**:

```python
[статус, причина]
```

Например:

```python
["OK", "clean"]
```

Именно список, а не кортеж `("OK", "clean")`: проверяющая система различает эти типы.

## Правила классификации

Правила применяются в указанном порядке. Как только одно из них сработало, функция возвращает результат.

| Порядок | Условие | Результат |
|---|---|---|
| 1 | ID автора входит в белый список | `["OK", "clean"]` |
| 2 | Сообщение является пустой строкой `""` | `["suspicious", "empty"]` |
| 3 | Длина сообщения меньше 5 символов | `["suspicious", "short"]` |
| 4 | Сообщение содержит подстроку `http` или хотя бы одну подозрительную фразу | `["suspicious", "bad words"]` |
| 5 | Сообщение содержит хотя бы один символ из набора запрещённых символов | `["spam", "greek"]` |
| 6 | Сообщение содержит хотя бы одну запрещённую фразу | `["spam", "spam words"]` |
| 7 | Ни одно из предыдущих условий не выполнено | `["OK", "clean"]` |

### Уточнения

- Для авторов из белого списка остальные правила не применяются: даже пустое, короткое или содержащее ссылку сообщение получает результат `["OK", "clean"]`.
- Пустая строка обрабатывается отдельно от остальных коротких сообщений.
- Длина определяется функцией `len(message)` в символах Unicode.
- Пробелы не удаляются: строка из четырёх пробелов не является пустой, но считается короткой.
- Поиск выполняется по подстроке, а не по отдельным словам.
- Регистр важен. Например, подстроки `http` и `HTTP` считаются разными.
- Предварительно преобразовывать сообщение к нижнему регистру не требуется.
- Порядок правил важен: сообщение, одновременно содержащее `http` и запрещённую фразу, получает результат `["suspicious", "bad words"]`.

## Проверяющая система

Проверяющая система использует файл `check.json`. Каждый тест имеет следующую структуру:

```json
{
    "id": 5,
    "input": "27763888|",
    "output": ["suspicious", "empty"]
}
```

Для каждого теста система вызывает `solve(input)` и сравнивает полученный результат с `output`, включая тип и содержимое результата.

Инструкция по запуску находится в файле `README.md`.
