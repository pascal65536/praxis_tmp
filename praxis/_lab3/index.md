# 1. Формат журнала

Каждая корректная запись занимает одну физическую строку и содержит четыре или шесть полей, разделённых символом `;`.

## Запись из четырёх полей

{% raw %}
```text
2026-10-18 12:00:01,000;vkkbot_100;INFO;🔄 Задача search для 101
```
{% endraw %}

Поля:

1. дата и время;
2. идентификатор воркера;
3. уровень сообщения;
4. событие.

## Запись из шести полей

{% raw %}
```text
2026-10-18 12:00:00,500;vkkbot_100;INFO;REQUEST;101;8б
```
{% endraw %}

Дополнительно присутствуют:

5. идентификатор пользователя;
6. полезная нагрузка.

## Корректность записи

Запись считается корректной, если выполняются все условия:

- строка содержит ровно четыре или шесть полей;
- время соответствует формату `%Y-%m-%d %H:%M:%S,%f`;
- воркер соответствует шаблону `vkkbot_\d+`;
- уровень равен `INFO`, `WARNING` или `ERROR`;
- поле события непустое;
- в записи из шести полей `user_id` состоит только из цифр.

Полезная нагрузка может быть пустой. Все остальные строки считаются некорректными: их нужно посчитать и пропустить, не завершая программу.

Для этого задания не нужно объединять traceback с предыдущей записью. Каждая его строка считается отдельной некорректной строкой.

# 2. Обязательная часть

Функция `solve(text)` должна вернуть словарь со следующими ключами.

| Ключ | Содержимое |
|---|---|
| `total_lines` | Общее количество физических строк |
| `valid_lines` | Количество корректных записей |
| `invalid_lines` | Количество некорректных строк |
| `unique_workers` | Количество уникальных воркеров в корректных записях |
| `requests` | Количество событий `REQUEST` |
| `cached` | Количество событий `CACHED` |
| `unique_users` | Количество уникальных пользователей, у которых есть `REQUEST` |
| `top_users` | Топ-10 пользователей по количеству `REQUEST` |
| `commands` | Количество команд запуска и остановки бота |
| `tasks` | Количество запусков задач каждого типа |

## Рейтинг пользователей

Каждый элемент `top_users` — словарь:

{% raw %}
```python
{"user_id": "101", "count": 5}
```
{% endraw %}

Правила:

- учитываются только корректные записи `REQUEST`;
- `CACHED`, `ERROR` и другие события не увеличивают счётчик обращений;
- `user_id` возвращается строкой;
- записи сортируются по убыванию `count`;
- при равном `count` используется сортировка по `user_id` в алфавитном порядке;
- возвращаются не более десяти записей.

## Команды

Словарь `commands` всегда содержит два ключа:

{% raw %}
```python
{
    "start": 0,
    "stop": 0,
}
```
{% endraw %}

`start` увеличивается только для `REQUEST` с полезной нагрузкой `▶️ Запуск бота`, а `stop` — только для `REQUEST` с полезной нагрузкой `⏹️ Остановка бота`.

## Типы задач

Начало задачи имеет вид:

{% raw %}
```text
🔄 Задача search для 101
```
{% endraw %}

Общий шаблон:

{% raw %}
```text
🔄 Задача <тип> для <user_id>
```
{% endraw %}

Словарь `tasks` содержит количество таких событий по типам задач. Завершение задачи не увеличивает этот счётчик. Если в журнале нет запусков задач, результат — пустой словарь `{}`.

## Пустой журнал

Для пустой входной строки все числовые показатели равны нулю, `top_users` равен `[]`, `tasks` равен `{}`, а оба значения `commands` равны нулю.

## Дополнительные правила

- Строки обрабатываются в порядке следования в файле, без сортировки по времени.
- Символ BOM (`\ufeff`) в самом начале входного текста игнорируется.
- Повторяющиеся записи не удаляются.
- Разбираются только корректные записи.
- Функция возвращает новые структуры данных и не выводит их в консоль.

# 4. Дополнительная часть 1. Длительность задач

Реализуйте функцию:

{% raw %}
```python
def analyze_task_durations(text):
    ...
```
{% endraw %}

Она возвращает статистику только по завершённым задачам.

Начало задачи:

{% raw %}
```text
🔄 Задача search для 101
```
{% endraw %}

Завершение:

{% raw %}
```text
✅ Задача search выполнена для 101
```
{% endraw %}

## Правила сопоставления

- События обрабатываются в порядке следования строк.
- Начало и завершение связываются по паре `(task, user_id)`.
- Для каждой такой пары хранится очередь времён начала.
- Завершение сопоставляется с самым ранним незакрытым началом — правило FIFO.
- Незакрытые начала и завершения без начала игнорируются.
- Длительность вычисляется в секундах как разность временных меток.
- Среднее значение округляется до трёх знаков после запятой.
- Если ни одной пары для типа задачи нет, этот тип в результат не включается.

Формат результата:

{% raw %}
```json
{
  "search": {
    "completed": 2,
    "average_seconds": 1.25
  }
}
```
{% endraw %}

# 5. Дополнительная часть 2. Рейтинг классов

Реализуйте функцию:

{% raw %}
```python
def top_classes(text, limit=10):
    ...
```
{% endraw %}

Она анализирует полезную нагрузку событий `REQUEST` и находит запросы вида:

{% raw %}
```text
8б
10 Т
5В
```
{% endraw %}

Правила:

- перед разбором удаляются пробелы по краям строки;
- запрос должен полностью соответствовать шаблону: одна или две цифры, необязательные пробелы и одна русская буква;
- ведущий ноль у номера класса удаляется преобразованием к `int`;
- буква приводится к нижнему регистру;
- пробелы внутри запроса удаляются;
- остальные запросы игнорируются;
- сортировка — по убыванию количества, затем по названию класса;
- возвращается не более `limit` записей.

Элемент результата:

{% raw %}
```python
{"class": "10т", "count": 3}
```
{% endraw %}
