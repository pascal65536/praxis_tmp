# Лабораторная работа №4. Основы ООП

В этой работе нужно реализовать четыре небольшие задачи: кошелёк, геометрические фигуры, двумерный вектор и иерархию сотрудников.

Полная постановка находится в файле [index.md](index.md).

## Что скачать

Для выполнения работы достаточно двух файлов:

- [student.py](student.py) — шаблон, в котором нужно написать решение;
- [check.py](check.py) — автономная проверяющая программа.

Сохраните оба файла **в одной папке**. Не переименовывайте их и не изменяйте имена классов, методов и функций в шаблоне.


```text
lab4/
├── student.py
└── check.py
```


Файл `check.py` предназначен для проверки и изменять его не нужно.

## Как выполнить работу

1. Откройте `student.py` в редакторе.
2. Последовательно реализуйте четыре задачи из `index.md`.
3. Сохраните файл.
4. Запустите проверку.
5. Исправьте ошибки и повторите проверку до получения полного результата.

Выполняйте решение самостоятельно. Не удаляйте готовый класс `Employee`: он используется в четвёртой задаче.

## Как запустить проверку

Откройте терминал в папке с файлами и выполните:


```bash
python3 check.py
```


Если в вашей системе команда называется `python`, используйте:


```bash
python check.py
```


Проверка использует только стандартную библиотеку Python. Устанавливать `pytest`, создавать виртуальное окружение или файл `requirements.txt` не требуется.

## Как читать результат

При полном успехе программа выведет:


```text
Пройдено проверок: 18 из 18.

Результаты по задачам:
  1. Wallet: 4/4
  2. Фигуры: 4/4
  3. Vector2D: 7/7
  4. Сотрудники: 3/3

Все проверки пройдены успешно!
```


Если решение неполное, чекер продолжит выполнение остальных проверок и покажет:

- общее число пройденных проверок;
- результат по каждой из четырёх задач;
- название каждой непройденной проверки;
- ожидаемый и фактический результат либо текст исключения.

Например, сообщение `Ожидалось: 1000. Получено: None` означает, что метод должен вернуть число, но сейчас возвращает `None`. Сообщение `TypeError` обычно указывает на несовпадение аргументов или неподдерживаемую операцию.

## Что проверяется

Всего выполняется 18 сценарных проверок:

1. **Wallet — 4 проверки:** создание объекта, отрицательный начальный баланс, пополнение, снятие, неверные операции и снятие всей суммы.
2. **Фигуры — 4 проверки:** периметры, суммарный периметр, пустой список и работа с дополнительным классом, имеющим метод `perimeter()`.
3. **Vector2D — 7 проверок:** сложение, умножение, создание новых объектов, обработка неподдерживаемых типов, равенство, строковое представление, хеширование, `set` и `dict`.
4. **Сотрудники — 3 проверки:** бонус сотрудника, наследование и атрибуты менеджера, расчёт бонуса менеджера на нескольких наборах данных.

Проверки независимы: ошибка в одной задаче не мешает увидеть результаты остальных.

## Технические коды завершения

Они пригодятся, если преподаватель запускает проверку автоматически:

- `0` — все проверки пройдены;
- `1` — есть непройденные проверки;
- `2` — не удалось загрузить `student.py`;
- `130` — проверка прервана пользователем.

Локальный чекер помогает самостоятельно подготовить решение. Порядок сдачи и итогового оценивания определяет преподаватель.
