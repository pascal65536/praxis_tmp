# Лабораторная работа №3: запуск и проверка

В этом каталоге находятся задание, шаблон решения, маленький учебный журнал и автономная проверяющая система. Внешние библиотеки и команда `pip install` не нужны: используется только стандартная библиотека Python.

Полная постановка находится в файле [index.md](index.md).

## 1. Состав комплекта

После добавления большого журнала структура должна быть такой:

```text
lab3/
├── index.md
├── README.md
├── student.py
├── check.py
├── check.json
├── expected_sample.json
└── data/
    ├── sample.log
    └── kuragino3.log
```

Назначение файлов:

- `student.py` — единственный файл, в котором нужно писать решение;
- `index.md` — условие обязательной и дополнительных частей;
- `data/sample.log` — маленький журнал для отладки;
- `expected_sample.json` — правильный базовый отчёт для `sample.log`;
- `check.py` — программа автоматической проверки;
- `check.json` — тестовые случаи;
- `data/kuragino3.log` — большой журнал, который студент добавляет самостоятельно.

Файл `kuragino3.log` не входит в скачиваемый комплект. Поместите уже имеющийся файл именно в каталог `data` и сохраните указанное имя.

Не переименовывайте и не изменяйте `check.py`, `check.json`, `expected_sample.json` и `data/sample.log`: проверка рассчитана на эти файлы.

## 2. Подготовка на Windows

Рекомендуется Python 3.10 или новее. Проверьте установку в терминале:

```bat
py -3 --version
```

Если команда `py` недоступна, попробуйте:

```bat
python --version
```

Далее в примерах используется `py -3`. Если на компьютере работает только `python`, заменяйте начало каждой команды:

```text
py -3 check.py  →  python check.py
```

Распакуйте или скопируйте комплект в короткий путь без кириллицы, например:

```text
C:\course\lab3
```

Это не обязательное требование, но так проще избежать ошибок при вводе пути и проблем в сторонних редакторах. Если в пути есть пробелы, заключайте его в кавычки.

В проводнике Windows желательно включить отображение расширений файлов. Иначе можно случайно создать `student.py.txt` вместо `student.py`.

## 3. Открытие терминала в каталоге работы

Запускайте команды из терминала, а не двойным щелчком по `check.py`: иначе окно может закрыться сразу после завершения, и результаты проверки не будут видны.

Удобные способы открыть терминал:

1. Откройте каталог `lab3` в проводнике, введите `cmd` в адресной строке и нажмите Enter.
2. Либо откройте «Терминал» или PowerShell и перейдите в каталог вручную.

Пример для командной строки:

```bat
cd /d C:\course\lab3
```

Пример для PowerShell:

```powershell
cd C:\course\lab3
```

Проверить содержимое текущего каталога можно командой `dir`.

## 4. Написание решения

Откройте `student.py` и реализуйте три функции согласно `index.md`:

- `solve(text)` — обязательная часть;
- `analyze_task_durations(text)` — дополнительная часть 1;
- `top_classes(text, limit=10)` — дополнительная часть 2.

Функция `solve(text)` получает содержимое журнала как строку. Она не должна самостоятельно открывать журнал, запрашивать путь через `input()` или печатать отчёт.

Чтение файла, запись JSON и обработка аргументов командной строки уже реализованы в шаблоне. Файловый интерфейс можно не изменять.

## 5. Запуск на маленьком журнале

В каталоге `lab3` выполните:

```bat
py -3 student.py data\sample.log report.json
```

При успешном запуске появится сообщение:

```text
Отчёт сохранён: report.json
```

Сравните содержимое созданного `report.json` с `expected_sample.json`. Для точной автоматической проверки используйте `check.py`, а не визуальное сравнение: порядок ключей и форматирование JSON значения не имеют, но структура, значения и типы данных проверяются строго.

Для большого журнала после его размещения в `data` команда выглядит так:

```bat
py -3 student.py data\kuragino3.log report-kuragino3.json
```

Контрольные значения для большого журнала приведены в `index.md`.

## 6. Автоматическая проверка

Обязательная часть и файловый интерфейс:

```bat
py -3 check.py
```

В этом режиме выполняются шесть функциональных тестов и одна проверка запуска `student.py` с созданием JSON — всего семь проверок.

Обязательная и обе дополнительные части:

```bat
py -3 check.py --advanced
```

В расширенном режиме выполняются одиннадцать функциональных тестов и одна проверка файлового интерфейса — всего двенадцать проверок.

При успехе программа выводит:

```text
Все выбранные проверки пройдены успешно!
```

Если решение неполное, проверка не останавливается на первой ошибке. Сначала выводится число пройденных проверок, затем диагностика неудачных тестов.

### Коды завершения

| Код | Значение |
|---:|---|
| `0` | Все выбранные проверки пройдены |
| `1` | Решение запустилось, но есть непройденные проверки |
| `2` | Ошибка запуска, аргументов, импорта или комплекта проверки |
| `130` | Выполнение прервано пользователем, например через Ctrl+C |

## 7. UTF-8, BOM и переводы строк

Комплект рассчитан на Windows, Linux и macOS:

- входные файлы читаются как UTF-8; BOM в начале файла допускается;
- JSON записывается в UTF-8 без BOM и с русскими символами без `\u`-экранирования;
- строки с `LF` и Windows-строки с `CRLF` обрабатываются одинаково;
- проверка не зависит от каталога, из которого был загружен `check.py`;
- дочерний процесс запускается тем же интерпретатором Python, которым запущен чекер;
- отчёт во время автоматической проверки создаётся во временном каталоге и не перезаписывает ваш `report.json`.

Если консоль Windows выводит ошибки кодировки или нечитаемые символы, используйте режим UTF-8:

```bat
py -3 -X utf8 check.py
py -3 -X utf8 check.py --advanced
```

Для запуска решения аналогично:

```bat
py -3 -X utf8 student.py data\sample.log report.json
```

При необходимости в `cmd` перед запуском можно переключить кодовую страницу консоли:

```bat
chcp 65001
```

Не сохраняйте исходные файлы в ANSI/Windows-1251. В редакторе выбирайте кодировку UTF-8.

## 8. Типичные проблемы

### «py не является внутренней или внешней командой»

Используйте `python` вместо `py -3`. Если и `python` не распознаётся, проверьте установку Python и параметр **Add Python to PATH** либо запускайте команды из терминала, встроенного в ваш редактор.

### «Не удалось загрузить student.py»

Убедитесь, что файл называется именно `student.py`, находится рядом с `check.py` и не содержит синтаксических ошибок. Также проверьте, что вне функций нет кода, который завершает программу или ждёт ввод.

### «Файл не найден: data\sample.log»

Проверьте структуру каталогов. Журнал `sample.log` должен находиться в подкаталоге `data`, а команды следует выполнять из каталога `lab3`.

### «student.py завершился с кодом 1»

Прочитайте сообщение об ошибке в выводе проверки. Чаще всего причина — исключение внутри решения, неправильный тип результата или невозможность записать JSON.

### Отчёт не совпадает с ожидаемым

Проверка сравнивает не только значения, но и типы. Например, `user_id` должен быть строкой, `count` — целым числом, `top_users` — списком, а `tasks` — словарём. Дополнительные ключи в отчёте также считаются ошибкой.

### Путь содержит пробелы

При ручном запуске с указанием полного пути используйте кавычки:

```bat
py -3 "C:\My Course\lab3\student.py" "C:\My Course\lab3\data\sample.log" report.json
```

Однако проще сначала перейти в каталог работы и использовать команды из разделов 5–6.

## 9. Что сдавать

Для проверки преподавателю нужен ваш заполненный `student.py`. По требованию преподавателя дополнительно можно приложить полученный `report-kuragino3.json` и снимок успешного результата:

```text
Режим проверки: базовая + дополнительная.
Пройдено проверок: 12 из 12.
Все выбранные проверки пройдены успешно!
```

Сам большой `kuragino3.log` повторно прикладывать не требуется.
