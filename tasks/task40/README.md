# API студентов: фильтрация, сортировка, пагинация — инструкция по проверке

## Что нужно сделать

Реализовать в файле `student.py` функцию `solve`, которая читает `students.json`
и возвращает отфильтрованный/отсортированный/обрезанный список студентов.

## Состав файлов

В одной папке должны находиться:

| Файл             | Назначение                                                   |
| ---------------- | ------------------------------------------------------------ |
| `student.py`     | Ваше решение (единственный файл, который вы меняете)         |
| `students.json`  | Данные студентов (менять нельзя)                             |
| `check.py`       | Скрипт проверки (менять нельзя)                              |
| `check.json`     | Список тестов: `setup`-файлы и `expected_file`-файлы         |
| `i1.py`…`i14.py` | Входные данные и вызов `solve(...)` для каждого теста        |
| `o1.py`…`o14.py` | Эталонные значения `ret` для каждого теста                   |
| `teacher.py`     | Эталонное решение (для справки)                              |

## Сигнатура функции

```python
def solve(sort=None, order="asc", filter=None,
          min_avg=None, max_missed=None, limit=5, offset=0):
    """Отфильтрованный/отсортированный/обрезанный список студентов."""
```

### Параметры

- `sort: str | None` — поле сортировки: `"name"`, `"avg"`, `"missed"`;
- `order: str` — `"asc"` (по умолчанию) или `"desc"`;
- `filter: str | None` — подстрока ФИО (регистронезависимо);
- `min_avg: float | None` — минимальный средний балл (включительно);
- `max_missed: int | None` — максимальное число пропусков (включительно);
- `limit: int | None` — размер страницы (по умолчанию `5`);
- `offset: int` — смещение (по умолчанию `0`).

### Возвращаемое значение

`list[dict]` — список словарей в исходном формате
(`full_name`, `grades`, `missed_classes`). Вспомогательное поле `avg`
в результат **не попадает**.

### Порядок операций

1. Чтение `students.json`.
2. Фильтрация (`filter`, затем `min_avg`, затем `max_missed`).
3. Сортировка по `sort` с учётом `order`.
4. Пагинация: `result[offset:offset + limit]`.

Пример:

```python
>>> solve(filter="ова", sort="name")
[{"full_name": "Белова Арина Максимовна", "grades": [5, 5, 4, 5, 5], "missed_classes": 0}, ...]
```

## Как запустить проверку

1. Сохраните все файлы в одной папке.
2. Напишите решение в `student.py`. Не изменяйте имя и сигнатуру функции.
3. Откройте терминал в папке с файлами и выполните:

   ```bash
   python3 check.py
   ```

   Если `python3` недоступен:

   ```bash
   python check.py
   ```

4. Дождитесь завершения проверки.

## Что вы увидите на экране

- для каждого теста — строку `PASS` или `FAIL`;
- для непройденных тестов — причину расхождения (какой индекс/ключ/значение
  не совпали);
- в конце — итог: сколько тестов пройдено из общего числа.

Пример:

```
✅ Тест 1: PASS
❌ Тест 2: FAIL
   Причина: ret[0]: ключи не совпадают. Ожидалось ['full_name', 'grades', 'missed_classes'], получено ['full_name', 'grades', 'missed_classes', 'avg']
...
==================================================
Итог: пройдено 13 из 14 тестов.
```

## Формат `check.json`

```json
{
    "tests": [
        {
            "id": 1,
            "description": "GET /students - получить весь список",
            "setup": "i1.py",
            "expected_file": "o1.py"
        }
    ]
}
```

- `id` — номер теста;
- `description` — человекочитаемое описание (в сравнении не участвует);
- `setup` — файл, который выполняется после `student.py`; должен определить `ret`;
- `expected_file` — файл с эталонным значением `ret`.

`check.json` **не изменяйте** — проверяющая система использует именно его.

## Как устроен один тест

1. `check.py` читает код `student.py`.
2. Для каждого теста создаётся **чистое** пространство имён.
3. В него выполняется `student.py` (определяется `solve`).
4. Выполняется `setup`-файл, например `i2.py`:

   ```python
   ret = solve(sort="name", order="asc")
   ```

5. Из `expected_file` (например, `o2.py`) загружается эталон — Python-литерал
   или JSON.
6. `ret` сравнивается с эталоном через `diff`:
   - `dict` — сравниваются наборы ключей и значения по ключам;
   - `list` — сравниваются длины и поэлементно;
   - `float` — с допуском `rel_tol=1e-9`, `abs_tol=1e-9`;
   - остальное — через `==`.

## Частые ошибки

| Симптом                                                       | Причина                                                        |
| ------------------------------------------------------------- | -------------------------------------------------------------- |
| `Переменная 'ret' не была создана в iN.py`                    | `solve` бросила исключение (например, не найден `students.json`) |
| `ret[0]: ключи не совпадают ... 'avg'`                        | В результат попало вспомогательное поле `avg`                  |
| `ret[0]['missed_classes']: ожидалось 0, получено 5`           | Неверный порядок операций (сортировка после пагинации и т.п.)  |
| `длина списка 10 вместо 5`                                    | Не учтён `limit` по умолчанию (`5`)                            |
| `длина списка 5 вместо 6`                                     | `offset` не применён (или применён дважды)                     |
| `ret[0]: ключи не совпадают ... ['avg']` в обратную сторону    | `avg` не удалён из итоговых словарей                           |
| `Сидорова` не найдена по `filter="ова"`                       | Регистрозависимое сравнение или сравнение по префиксу          |
| `Тест 7: FAIL` (min_avg=4.5)                                  | Неверная формула среднего или нестрогое сравнение (`>=`)       |
| `sort="missed", order="desc"` даёт не тот порядок             | Перепутано направление `reverse`                               |
| `FileNotFoundError: students.json`                            | Файл данных лежит не рядом со `student.py`                     |
